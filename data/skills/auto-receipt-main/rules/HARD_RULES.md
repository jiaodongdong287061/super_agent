# AutoReceipt V1.2 - 硬性规则

> 以下规则 Agent 必须严格遵守，不可偏离。

## 版本范围

| 版本 | 支持范围 | 状态 |
|-----|---------|------|
| V1.0 | 差旅报销（机票/火车票/打车/住宿/餐补） | ✅ 已发布 |
| V1.1 | 新增机票代订服务费、生成后验证流程 | ✅ 已发布 |
| V1.2 | N:1 特殊费用合并规则、文件处理强化 | ✅ 当前版本 |
| V2.0 | 餐饮/招待费用报销 | 🔜 规划中 |

### 当前版本限制

> **重要**：当前版本（V1.2）仅支持**单个出差行程**的报销处理。
>
> 如果用户有多个出差项目需要报销，需要先将发票按出差项目拆分到不同文件夹，然后逐个文件夹进行自动化报销。

## 2. 报销明细 Excel 填写规则

### Excel 文件结构

| 行号 | 内容 |
|------|------|
| 第 1 行 | 只有 A1 单元格填写「报销明细」，其他单元格留空 |
| 第 2 行 | 表头：起 - 年月日、止 - 年月日、起 - 地点、止 - 地点、费用种类、单据张数、金额 |
| 第 3 行起 | 数据行 |

### 列定义

| 列名 | 填写内容 | 格式 | 示例 |
|------|---------|------|------|
| 起 - 年月日 | 费用起始日期 | YYYY-MM-DD | 2025-02-26 |
| 止 - 年月日 | 费用结束日期 | YYYY-MM-DD | 2025-02-28 |
| 起 - 地点 | 出发城市 | 城市名 | 北京、上海 |
| 止 - 地点 | 目的城市 | 城市名 | 北京、上海 |
| 费用种类 | 见「费用种类枚举」 | 枚举值 | 机票、打车费 |
| 单据张数 | 默认为 1，餐补为出差天数 | 整数 | 1、2、3 |
| 金额 | 发票金额 | 数值，保留 2 位小数 | 640.00、78.95 |

### 费用种类（仅限以下枚举值）

```
打车费、机票、火车票、餐补费、住宿费、其他餐费、办公用品、饮用水
```

**不允许使用枚举值以外的任何值。**

## 3. 起止日期填写规则

### 按费用类型

| 费用种类 | 起 - 年月日 | 止 - 年月日 | 说明 |
|---------|----------|----------|------|
| 机票/火车票 | 票面上的乘车日期（**不是开票日期**） | 票面上的到达日期（单程票与起日期相同） | 例如：火车票上"2025 年 11 月 10 日 14:42 开"→ 起日期=2025-11-10 |
| 打车费 | 行程单上的出发日期 | 行程单上的到达日期 | 通常起止日期相同 |
| 住宿费 | 入住日期 | 退房日期 | 需结合机票/火车票行程 + 发票数量推断 |
| 餐补 | 出差开始日期（从去程机票/火车票推断） | 出差结束日期（从返程机票/火车票推断） | 从机票/火车票推断 |
| 其他费用 | 开票日期 | 开票日期 | |

### 住宿费起止日期判断流程

**步骤 1：收集信息**
- 从机票/火车票推断出差日期范围（去程日期 ~ 返程日期）
- 识别酒店发票上的「数量」字段（住宿天数）

**步骤 2：自动判断（满足以下条件）**
- 只有 1 张酒店发票
- 发票「数量」= 出差天数 - 1（或合理天数）
- 入住日期 = 去程日期（或去程后一天）
- 退房日期 = 返程日期（或返程前一天）

**步骤 3：必须向用户确认的情况**
- 有多张酒店发票
- 发票「数量」与行程日期不对应
- 无法确定入住/退房日期

**示例：**
```
出差行程：2025-02-26 成都→杭州，2025-02-28 杭州→成都
酒店发票：数量=2
→ 入住日期=2025-02-26，退房日期=2025-02-28（共 2 晚）
```

## 4. 起止地点填写规则

### 按费用类型

| 费用种类 | 起地点 | 止地点 | 说明 |
|---------|-------|-------|------|
| 机票 | 去程=用户出发城市，返程=用户目的城市 | 去程=用户目的城市，返程=用户出发城市 | 根据去程/返程判断方向 |
| 火车票 | 去程=用户出发城市，返程=用户目的城市 | 去程=用户目的城市，返程=用户出发城市 | 根据去程/返程判断方向 |
| 打车费 | 行程单上的出发地（城市级别） | 行程单上的到达地（城市级别） | 需要从行程单推断城市 |
| 住宿费 | 用户目的城市 | 用户目的城市 | 出差目的城市 |
| 餐补 | 用户出发城市 | 用户出发城市 | 固定为出发城市 |
| 其他费用 | 留空 | 留空 | 不填 |

### 城市级别要求

- 只填写城市名，不填区县、具体地址
- 例如：「北京市朝阳区」→ 「北京」
- 例如：「上海市静安区」→ 「上海」

## 5. 餐补特殊规则

### 城市分类

| 分类 | 城市 | 标准（元/天） |
|------|------|-------------|
| 一类 | 北京、上海、广州、深圳 | 120 |
| 二类 | 其他直辖市、计划单列市及省会城市 | 80 |
| 三类 | 其他地区 | 80 |

### 填写方式

| 字段 | 值 |
|------|-----|
| 起 - 年月日 | 出差开始日期（从机票/火车票推断） |
| 止 - 年月日 | 出差结束日期（从机票/火车票推断） |
| 起 - 地点 | 用户出发城市 |
| 止 - 地点 | 出发城市 |
| 费用种类 | 餐补费 |
| 单据张数 | 出差天数 |
| 金额 | 根据城市分类计算 |

### 餐补计算公式

```
出差天数 = (返程日期 - 去程日期) + 1
餐补金额 = 目的地城市标准 × (出差天数 - 1) + 终点城市标准 × 1
```

### 计算说明

- 出差天数从出发当天到返程当天
- 出发日、返程日各按 1 天计算
- 在目的地停留的天数（出差天数-1）按目的地城市标准计算
- 返程日（1天）按终点城市（返程到达城市）标准计算

**示例：**
```
去程：2025-07-14 北京→西安
返程：2025-07-21 西安→北京
出差天数 = (7/21 - 7/14) + 1 = 8 天

西安（二类城市）：80 元/天
北京（一类城市）：120 元/天

餐补金额 = 80 × (8-1) + 120 × 1 = 560 + 120 = 680 元
起止地点：北京 → 北京
```

## 6. 附属单据处理规则

### 6.1 行程单（打车费附属）

### 匹配方式

1. **优先**：金额精确匹配（发票金额 = 行程单金额）
2. **其次**：金额模糊匹配（差距在 1 元以内，视为同一笔）
3. **不匹配**：没有匹配到的行程单不参与报销

### 处理方式

- **发票**：填入报销明细 + 重命名文件 + 按费用类型归类
- **行程单**：不填入报销明细，但需要重命名文件 + 按费用类型归类
- 行程单与发票匹配后，打车费的起止地点从行程单提取

### 行程单处理规则

1. 行程单不参与报销明细的填写
2. 行程单需要按规则重命名文件
3. 行程单用于提取打车费的起止地点信息

### 6.2 登机牌（机票附属）

### 处理方式

- **登机牌**：不填入报销明细，但需要重命名文件
- 登机牌用于提取机票的出发地/到达地信息（特别是三字码转城市名）
- 登机牌不单独成行，仅作为机票费的附属凭证

### 6.3 水单（住宿费附属）

### 处理方式

- **水单**：不填入报销明细，但需要重命名文件
- 水单用于佐证住宿天数
- 水单不单独成行，仅作为住宿费的附属凭证

## 7. 去程/返程判断规则

### 判断逻辑

根据发票/行程单的行程信息，对比用户输入的出发/到达城市：

```
1. 从发票/行程单提取：出发城市、到达城市
2. 对比用户输入的出发城市（A）和目的城市（B）：
   - 出发城市=A 且 到达城市=B → 去程
   - 出发城市=B 且 到达城市=A → 返程
```

### 示例

```
用户输入：出发城市=成都，到达城市=杭州

发票 1 提取：出发城市=成都，到达城市=杭州
→ 去程 → 报销明细填写：成都 → 杭州

发票 2 提取：出发城市=杭州，到达城市=成都
→ 返程 → 报销明细填写：杭州 → 成都
```

### 备用方案

如果无法从发票提取到城市信息：
- 优先使用发票上的 departure 和 arrival 字段
- 如果仍无法判断，询问用户确认

## 8. 数据优先级规则

当多个数据源给出不同信息时，按以下优先级：

### 费用类型
1. 销售方名称（含关键词）
2. 发票上的 fee_type 字段
3. Agent 综合判断

### 起止地点
1. 行程单上的出发/到达地点（打车费）
2. 发票上的出发/到达地点
3. 用户输入的出发/到达城市（机票/火车票）

### 日期
1. 火车票/机票的票面乘车日期
2. 发票上的开票日期
3. 行程单上的日期

## 9. 异常处理规则

### 交互方式

**所有用户交互必须使用 `AskUserQuestion` 工具，以表格形式呈现选项，让用户点击选择，而不是在对话框中输入。**

### 必须跳过的情况
- 金额为 0 或无法识别
- 日期无法识别且无法推断

### 需要询问用户的情况（发现后停止并等待确认）

使用 `AskUserQuestion` 工具，提供清晰的选项：

| 异常类型 | 具体情况 | 确认内容 | 选项示例 |
|---------|---------|---------|---------|
| 行程异常 | 没有返程票 | 是否还没购买返程票 | "是的，还没买" / "应该有返程票" |
| 行程异常 | 多张返程票 | 是否是多次独立出差 | "同一次出差" / "多次出差，分开处理" |
| 行程异常 | 火车票到达城市与用户输入不符 | 确认正确的出发/到达城市 | "使用发票中的城市" / "使用我输入的" |
| 行程异常 | 返程日期早于去程 | 确认正确的行程日期 | "发票日期有误" / "我的输入有误" |
| 分配异常 | 打车费日期在出差日期范围外 | 是否属于本次出差 | "属于本次出差" / "不属于，跳过" |
| 分配异常 | 住宿费天数与行程天数差异大 | 确认住宿天数 | "X 晚" / "手动输入" |
| 分类异常 | 销售方与费用类型明显不匹配 | 确认费用类型 | 从枚举值中选择 |
| 餐补异常 | 出差天数 <1 或 >30 | 确认出差天数 | "天数正确" / "重新计算" |
| 其他 | 住宿费起止日期无法自动确定 | 多张酒店发票或数量与行程不匹配 | 提供具体日期选项 |
| 特殊费用 | 只有特殊费用发票（如只有高速通行费） | 询问如何处理 | "跳过" / "单独报销" |

### 自动处理的情况
- 正常识别的发票 → 自动分类
- 正常的行程单匹配 → 自动匹配
- 合理的日期范围 → 自动推断

## 11. 特殊费用合并规则

**核心原则：特殊费用发票不单独成行，而是合并到对应的主费用发票中，通过「单据张数」字段体现实际票据数量。**

### 11.1 费用合并规则总表

| 特殊费用类型 | 合并到费用种类 | 单据张数计算 | 金额计算 | 关联依据 |
|-------------|--------------|-------------|---------|---------|
| 民航发展基金 | 机票 | +1 | +50 元 | 备注栏的起止地点、乘客姓名、日期 |
| 高速通行费 | 打车费 | +N（实际张数） | +实际金额合计 | 关联同一张打车发票的所有通行费，不限日期 |
| 火车票退改签费 | 火车票 | +1 | +实际金额 | 销售方都是「中国铁路」、日期相近 |
| 飞机保险费 | 机票 | +1 | +实际金额 | 日期相近、乘客姓名匹配 |
| 机票代订服务费 | 机票 | +1 | +实际金额 | 销售方与机票相同（旅行社/航空公司）、日期相近 |

### 11.2 民航发展基金

**特征：**
- 单独开具的发票
- 金额固定 50 元
- 备注栏包含：起止地点、乘客姓名、航班日期

**合并规则：**
```
示例：
- 机票发票：北京→西安，票价 1000 元，2025-06-08
- 民航发展基金发票：备注"北京 - 西安，乘客张三"，50 元，2025-06-08

报销明细填写：
| 起 - 年月日 | 止 - 年月日 | 起 - 地点 | 止 - 地点 | 费用种类 | 单据张数 | 金额 |
|------------|------------|---------|---------|---------|---------|------|
| 2025-06-08 | 2025-06-08 | 北京 | 西安 | 机票 | 2 | 1050.00 |
```

**关联判断：**
1. 日期相同或相近（±1 天）
2. 备注栏的起止地点与机票一致
3. 乘客姓名与购买方一致

### 11.3 高速通行费

**特征：**
- 通用机打发票
- 销售方：高速公路有限责任公司
- 有通行日期、金额

**合并规则：**
```
示例：
- 打车发票：2025-02-14，成都，56 元
- 高速通行费发票：2025-02-14，10 元

报销明细填写：
| 起 - 年月日 | 止 - 年月日 | 起 - 地点 | 止 - 地点 | 费用种类 | 单据张数 | 金额 |
|------------|------------|---------|---------|---------|---------|------|
| 2025-02-14 | 2025-02-14 | 成都 | 成都 | 打车费 | 2 | 66.00 |
```

**关联判断：**
1. 通行费关联同一张打车发票（不限日期）
2. 城市匹配（从收费站名称推断城市）
3. 当行程单覆盖多段行程（如出发+返程），所有相关的高速通行费都合并到该行程单对应的打车费行

**N:1 合并示例（多张通行费合并到同一打车费行）：**
```
- 打车发票（含行程单）：覆盖出发+返程两段行程，打车费 300 元
- 高速通行费（出发日）：10 元
- 高速通行费（返程日）：10 元

报销明细填写：
| 起 - 年月日 | 止 - 年月日 | 起 - 地点 | 止 - 地点 | 费用种类 | 单据张数 | 金额 |
|------------|------------|---------|---------|---------|---------|------|

> **注意**：多张高速通行费关联同一张打车发票时，必须全部合并到同一行，禁止将通行费单独列为打车费行。

**边界情况：**
- 如果只有高速通行费发票，没有打车费发票 → **询问用户确认**

### 11.4 火车票退改签费

**特征：**
- 销售方：中国铁路
- 费用类型：退票费/改签费
- 金额：手续费

**合并规则：**
```

- 退票费发票：2025-04-27，11.50 元

1. 销售方都是「中国铁路」
2. 开票日期相近（±3 天）

**边界情况：**
- 如果只有退改签费发票，没有对应火车票 → **询问用户确认**

### 11.5 飞机保险费

**特征：**
- 单独开具的发票
- 销售方：保险公司
- 金额：通常 20-30 元

**合并规则：**
```
示例：
- 机票发票：2025-06-08，北京→西安，1000 元
- 飞机保险费发票：2025-06-08，30 元

报销明细填写：
| 起 - 年月日 | 止 - 年月日 | 起 - 地点 | 止 - 地点 | 费用种类 | 单据张数 | 金额 |
|------------|------------|---------|---------|---------|---------|------|
| 2025-06-08 | 2025-06-08 | 北京 | 西安 | 机票 | 2 | 1030.00 |
```

**关联判断：**
1. 日期相近（±1 天）
2. 乘客姓名与购买方一致

### 11.6 合并优先级

当一张特殊费用发票可能对应多张主发票时：
1. **优先**：日期最接近的主发票
2. **其次**：金额匹配（如高速通行费与打车费金额之和等于行程单总额）
3. **再次**：城市/地点匹配

如果仍无法确定，**询问用户确认**。
